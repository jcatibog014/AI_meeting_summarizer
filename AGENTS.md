# AGENTS.md

This file guides AI coding agents (Claude Code, Codex, Cursor, Copilot and others) working in this repository.

## Overview

**Sticky Minutes** ("The meeting stuck. Here's what matters."), an AI meeting summarizer in Python (Flask). The repo is `AI_meeting_summarizer` and the Python package is `stickyminutes`. You paste or upload a meeting transcript; Claude turns it into a summary, key points, decisions, action items and open questions; the app CHECKS the answer before it is saved. The plan is `docs/PLAN.md`.

It is a learning project for **LLM APIs, structured outputs and validation**, so those parts stay easy to read: short comments that explain *why*, the official `anthropic` SDK, Pydantic for the answer's shape, checks written by hand, and no extra libraries unless the owner asks for them. Write the README in simple (A1-level) English.

Python 3.13 is at `%LOCALAPPDATA%\Programs\Python\Python313\python.exe`. Use the virtual environment:

- Install: `.venv\Scripts\python -m pip install -r requirements.txt` (create `.venv` with `python -m venv .venv` first if it's missing).
- First time: `.venv\Scripts\flask --app stickyminutes upgrade-db` (makes the tables), then `.venv\Scripts\flask --app stickyminutes create-owner` (your login). Or click Try the demo.
- Claude: put `ANTHROPIC_API_KEY=...` in `.env` (git ignores it; copy `.env.example`). Without a key the app runs in **practice mode** (`llm.FakeClaude`), and every page says so.
- Run: `.venv\Scripts\flask --app stickyminutes run --debug --port 5016`, then open http://127.0.0.1:5016. (Ports: Swap Meter 5000, Ambon Alert 5001, Ang Gastos! 5002, Sangkap 5003, Gawi 5004, Akda 5005, Hire Wire 5006, Plan-It 5007, ShiroMoto 5008, DFJC 5009, Ticket Tock 5010, Tally Ho! 5011, J: Drive 5012, Right On Cue 5013, Pulse Check 5014, Paper Plane 5015.)
- Test: `.venv\Scripts\python -m pytest`. Every test gets a fresh SQLite file and **never calls Claude or the internet** (`ANTHROPIC_API_KEY` is empty in tests, so `FakeClaude` answers). Set `TEST_DATABASE_URL` to an **empty** PostgreSQL database to run the same tests there. SQLAlchemy warnings fail the tests (`pytest.ini`).
- Other commands: `set-password <email>`, `purge-demos`.

## Architecture

- **The login cookie is `stickyminutes_session`, not Flask's `session`:** browsers keep cookies per host, not per port, so the owner's other Flask apps on 127.0.0.1 would overwrite it (`tests/test_auth.py::test_the_login_cookie_has_its_own_name`).
- **Accounts (`auth.py`):** no sign-up, because every summary is a paid Claude call on the owner's key. The OWNER is made from the PC (`create-owner`), logs in by email, and has the one real workspace. Hashes from Werkzeug; 5 wrong passwords lock the account for 15 minutes, one address may try 30 logins per 15 minutes (`limits.py`). `load_user()` checks `session_version` (a password change logs out every other cookie) and a demo's expiry, and puts `g.user` / `g.workspace` on the request.
- **Demo (`seed.py`, `views/demo.py`):** Try Demo makes a sandbox `Workspace` ("Kape Cloud Meetings") with one person, Lea Ramos. Nobody can log in to a demo with a password; demo users start with a random `session_version`; `workspaces` and `users` use `sqlite_autoincrement`, so a deleted demo's ids are never handed out again. Demos are deleted after 24 hours (`seed.purge`, on every Try Demo click and by `purge-demos`). At most 20 at once, 10 per network an hour (not with `--debug`). **Every page the demo can open must show an example, so add sample data with every new feature** (`seed.fillers`).
- **Transcripts (`transcripts.py`):** every input becomes numbered `Line(n, speaker, at, text)` rows, saved as `transcript_lines` (UNIQUE meeting + n). **The numbers never change once saved**: Claude's evidence points at them and `checks.py` checks the quote is on that line. Pasted text / `.txt` / `.docx` ("Maria: ...", a time in front like "[00:01:23]", or Google Meet's "Maria Santos 00:00:03" on its own line, whose words follow) go through `parse_plain`; a line without a name goes on with the last speaker. `.vtt` (Zoom writes "Name: ..." in each cue, Teams writes `<v Name>`) and `.srt` go through `parse_cues`, which joins a speaker's cues that follow each other (up to `MERGE_CHARS`), because subtitles cut sentences into pieces. Pasted text that has cue times is read as cues. A speaker name is at most 4 words and each word starts with a capital, is a number ("Speaker 1") or is a name particle ("dela"), so "So here's the thing: ..." stays words. Limits: 2 MB a file, `MAX_CHARS` 300,000, `MAX_LINES` 5,000, at least `MIN_WORDS` 12; bytes are UTF-8 (BOM dropped) or Windows-1252, NUL bytes mean "not text". Every problem is a `TranscriptProblem` with a plain message for the form. `numbered()` is the text Claude reads: `[12] Maria Santos (00:03:10): ...`.
- **Meetings (`meetings.py`, `views/meetings.py`):** `load(s, workspace, id)` is the only way a page finds a meeting; another workspace's meeting is a 404, never a 403. A meeting with no title gets "Meeting on 24 Nov 2026" and `title_from_user` False (the summary may then name it). The demo holds at most 30 meetings. A meeting's page (`meeting.html`) has the transcript (each line `id="line-N"`, lit by `:target`), the Details form and Delete; later stages fill its `notes`, `head_actions` and `side` blocks through `page_extras`. Statuses: `views/meetings.STATUS`.
- **The answer's shape (`schema.py`), the structured-outputs lesson:** `MeetingNotes` (title, overview, key_points, decisions, action_items, open_questions; every item has 1-3 `Evidence(line, quote)`) is written ONCE in Pydantic and does two jobs. (1) The API's layer: `llm.py` sends `anthropic.transform_schema(MeetingNotes)` as `output_config.format`, so the answer is always JSON of that shape; transform_schema keeps what the API can enforce (types, required, enums, `minItems`) and moves the rest (lengths, `maxItems`, ranges) into the field descriptions. (2) Our layer: `schema.validate(text)` runs Pydantic on the text and turns every failure into a `Problem(layer, path, message)` ("schema" for a wrong type or missing field, "rules" for a broken length/range/sentence count). `messages.parse()` is NOT used: it raises on a failed validator and loses the raw answer the repair turn needs (`docs/PLAN.md`, Where the Build Differs).
- **Talking to Claude (`llm.py`), the LLM API lesson:** `Claude.summarize()` calls `client.beta.messages.create` (the beta endpoint for the refusal fallback: `betas=["server-side-fallback-2026-07-01"]`, `fallbacks="default"`, not for Haiku), `max_tokens` 16,000, `output_config={"effort": "medium", "format": ...}`, no streaming, no `thinking` (adaptive is the default and can't be turned off on Opus 5.5), no `temperature`. It reads `stop_reason` BEFORE the content (`check_stop`: `refusal` with its `stop_details.category`, `max_tokens`), keeps the answer's content blocks (thinking included) to send back unchanged, notes a fallback (`usage.iterations`), and counts tokens (cache reads/writes too). SDK errors become `LLMError(code, message, retry)`, caught most specific first (auth, permission, rate limit, too large, bad request, 5xx/529, timeout, connection). `count_tokens()` is free and is asked before a run. The SDK is 2.x and uses `httpx2`. **`FakeClaude`** has the same methods: tests give it a `script` (dicts, broken strings, `(stop_reason, text)` tuples, `LLMError`s); with no script it writes **practice notes** from the transcript's own words (decided/agreed lines, "I'll ..." lines with their speaker as owner, questions), every quote copied from its line. `client_for(app)` makes one per app: the real Claude with `ANTHROPIC_API_KEY`, else FakeClaude (practice mode); tests set `app.extensions["claude"]`.
- **Running a summary (`summarize.py`), the validation lesson:** `start()` refuses a meeting already running, estimates the cost (`count_tokens` + `OUTPUT_GUESS` output tokens), checks the budget and makes a queued `Run`; the view commits, then `launch()` runs `work()` in a daemon thread (`RUN_IN_THREAD`; tests run it inline). The loop: ask Claude, `schema.validate`, then the `reviewers` (layer 3, checks.py), save every problem as a `RunIssue` (attempt, layer, path; earlier ones marked `fixed` when gone), and if there are problems send a **repair turn** (the answer's content blocks back unchanged + "Your answer had these problems: ...; return the whole answer again"), at most `MAX_ATTEMPTS` 3 in all. The first user message is the transcript block (`<transcript>` + `transcripts.numbered`, `cache_control` ephemeral, so repairs read it from the cache) and then the meeting's facts (title or "name it", date with weekday, speakers). The best answer with the right shape is saved (`save_notes` replaces the meeting's `items`), its doubtful items FLAGGED (`Item.flag`), and the run/meeting become `needs_review`; with no good shape at all the run fails. A refusal or API error fails the run with its plain message (a refused answer is still counted). A run older than `STALE_AFTER` (10 min) still queued/running died with the server: `expire_stale()` marks it failed. The meeting page polls `/meetings/<id>/status.json` every 2 s (`app.js setUpStatusWatch`) and reloads. Prompts are files, `prompts/v1.md`; a run stores its `prompt_version`, `model`, `served_model`, `effort`, tokens, `cost_micros`, `estimate_micros`, `stop_reason`, `raw_output`.
- **Layer 3: grounding and business rules (`checks.py`, `summarize.reviewers`):** needs the transcript, so it runs after Pydantic. Each evidence quote must be on its line, compared with `normal()` (lowercase, straight quotes, one space, no punctuation at the ends); a quote on ANOTHER line is reported with the right line, a quote nowhere is "copy the words exactly"; a line that doesn't exist says the range. `found[(section, i, j)]` records each quote's result, saved on the item's evidence (`found` true/false: the chip's tick or dashed red). Action items: the owner must be a speaker or a name said in the meeting (`match_owner`; a unique first name becomes the full speaker label); the due date is never before the meeting or 2 years after; `resolve_due()` works out clear phrases from the meeting's date ("today", "end of day", "tomorrow", a weekday = the next one, never the same day, "December 15", "3rd January", "the 10th") and leaves vague ones alone ("next Friday", "next week", "soon"); a missing due date is filled in, a different one is a problem. Twins in one part are merged (`merge_twins`, evidence joined). **What is certain is fixed quietly** (owner names, dates, twins); everything else is a `Problem` for the repair turn, and what is left after the last try becomes `Item.flag` (the note gets a dashed outline and its reason; the page says how many need a look).
- **Review & Proof (`views/review.py`, `_note.html`, `item_edit.html`):** every note on the board (`_notes.html`: the overview, "N of M notes checked", then the four columns) has its line chips (a tick when the quote was found, red dashed when not; a click lights the transcript line, `app.js setUpLineLinks`), a "Proof" fold with each quote and its line, and Accept / Reject (`POST /items/<id>/review`, `decision` accept / reject / undo; `Item.review`) and a round pencil Edit. Editing (`/items/<id>/edit`, the proof beside the form) sets `edited` and `review = "accepted"`; an action item's owner is chosen from the speakers (or Unassigned), and a changed due date drops the meeting's `due_phrase`. `load_item()` goes through `meetings.load()`, so another workspace's note is a 404. Run again replaces the notes (the button asks first).
- **Action Tracker (`actions.py`, `views/actions.py`, `actions.html`):** every action item (an `Item` with kind "action") from every meeting in the workspace, rejected ones left out. Tabs Open / Overdue (open, due before today in the workspace's zone) / Done / All with counts, an owner filter (Everyone, each owner, Unassigned `-`), soonest due first and no date last. A tick box marks done or opens it again (`POST /items/<id>/done`, `done` 1/0, `next` checked by `auth.safe_next`); action notes on the meeting page have Done / Reopen too. The menu shows the open count (`open_actions`). **The calendar feed** `/actions/calendar/<token>.ics`: no login, so the link is a signed token (`tokens.make("calendar", workspace id, feed_nonce)`); "Make a new link" adds 1 to `workspaces.feed_nonce` (migration 0004) and the old link is a 404. Open items with a due date are all-day events (UID `action-<id>@stickyminutes`), text escaped (`ics_text`) and lines folded at 75 bytes (`fold`), CRLF endings.
- **The spending guard (`budget.py`):** the site's daily cap (`DAILY_CAP_CENTS`, the sum of `usage_ledger` for today's UTC day plus the new run's estimate; owner and demos alike) and a demo's `DEMO_RUNS_PER_DAY` (3), counted at START in `limits.py` under `demo-runs:<workspace>:<day>` so deleting a meeting gives nothing back. `usage_ledger` rows survive a deleted demo (`workspace_id` SET NULL). Practice mode costs nothing and has no limits. Money: `pricing.py` (micro-dollars; Opus 5.5 $4/$20, Sonnet 5.5 $2/$10, Haiku 5.5 $0.10/$0.50 per million tokens).
- **Settings (`views/settings.py`):** your account, the workspace (name, time zone), the Claude model (`pricing.MODELS`: Opus 5.5 by default, Sonnet 5.5, Haiku 5.5), the theme and Log out. Later modules add sections with `actions` / `extras`.
- **Database:** SQLAlchemy 2.0 ORM (typed `Mapped[...]`), plain (not Flask-SQLAlchemy). `db.py` makes one engine per app and one session per request: `db.session()`; code outside a request (the summarizing thread) uses `db.new_session()` and closes it. SQLite locally (`instance/stickyminutes.sqlite`, WAL), PostgreSQL (**Neon**, psycopg 3) when `DATABASE_URL` is set. **Money is in micro-dollars** (an int; `pricing.py`).
- **Migrations: Alembic**, in `stickyminutes/migrations/`. `flask --app stickyminutes upgrade-db` runs them (with SQLite's foreign keys off during the run, so a table rebuild can't cascade-delete rows); Render runs it before gunicorn.
  - **To change the schema:** edit `models.py`, then `.venv\Scripts\alembic revision --autogenerate -m "what changed" --rev-id 000N`, **read the new file and fix it** (booleans default to `sa.true()` / `sa.false()`, never `sa.text('1')`; a new NOT NULL column needs a `server_default`), and commit it. `tests/test_migrations.py` fails if the models and the migrations disagree.
  - Every foreign key to a parent that is deleted in bulk (`ON DELETE CASCADE` / `SET NULL`) needs an index that STARTS with that column (`test_bulk_deleted_parents_have_an_index_for_each_child`).
- **Every page works without JavaScript.** `app.js` only adds extras. The CSP has no inline scripts or styles, so **never use `style=""` or inline `<script>`** (`tests/test_look.py`).
- Commit messages and PR bodies go through files (`git commit -F`, `gh pr create --body-file`): PowerShell 5.1 breaks quotes in arguments.

## UI rules (the owner's priority is neatness)

- **Look: "Sticky notes".** A warm paper board with a faint dot grid (`--board`, `--board-dot`); notes in four soft colours, each a little tilted: green Key Points, blue Decisions, yellow Action Items, pink Open Questions (`--note-*`); Kalam (a marker hand) for headings, Nunito for text, both self-hosted in `static/fonts/` (Fontsource 5); marker blue buttons (`--accent`); page titles have a yellow highlighter swipe (`.marker`). The logo is two sticky notes (`_icons.html logo()`, the same picture as `static/icons/logo.svg`). Dark mode (a deep slate board with muted notes) is defined twice in `style.css` (device setting + the choice in Settings); change both blocks together. `tests/test_look.py` checks both themes for 4.5:1 text (on every note colour too) and 3:1 control edges.
- **Settings holds the controls, and the menus only navigate.** The theme and Log out are in Settings only; the menu's bottom row (your name) opens Settings.
- **Messages are toasts** (`_toasts.html`, bottom right): `flash(msg)` fades after 6 seconds; `flash(msg, "error")` stays until closed.
- **No decorative emoji.** Icons are the line SVGs in `_icons.html`.
- **Page titles are bare:** `page_head(title)` from `_macros.html`, with no line of text under the title.
- **Title Case** for the menu, page titles, section headings, tabs and empty-state titles. **Sentence case** for everything else: buttons ("New meeting", "Run again"), labels, hints, messages. The main button of a page is last on the right.
- Controls are the same height (`--control-height`). Sizes in `rem`; the root font steps up at 1600 / 1920 / 2300px. Tabs are pills that wrap, never a sideways scroll. Phone layouts fit the screen with no sideways scrolling.
- The sidebar shows from 56rem up; below that, a top bar with a Menu button.
